# The engine functions a mod may attach to through wxl.point: Before, Replace or After.
#
# This file is the list; everything else is generated from it by core/tools/points/generate_points.py
# (the contract's sdk/include/wxl/points.def, the x86 detours' include/wxl/points/x86.def, the
# recompiled client's WarcraftXL/Points.gen.h) and inserted into the fork by insert_points.py. A
# point is added by one line here and a regeneration; nothing is written by hand in core or the fork.
#
# One point per line, in the order of their ids (append only: a point is never moved or renamed):
#
#   address  name  policy  thread  stability  [# what a modder should know]
#
#   address    the function's address in Wow.exe 12340, as its OFFSET tag in the fork writes it; `-`
#              for a function the fork tags // INLINED: the 2008 compiler copied it into its callers,
#              so it exists on the recompiled client (x64) only, unless a deinlined line (below)
#              gives the x86 runtime a recompiled caller to reach it through.
#   name       the fork's qualified name: the point's name for good, even if the fork renames it.
#   policy     replace (Before, Replace and After) or observe (Before and After only).
#   thread     main (the client's main thread; a Lua mod may attach) or any (C and C++ only).
#   stability  stable (its signature never changes: a change makes a new point, name@2) or
#              provisional (may change with a feature of the contract).
#
# An inlined copy of a point's function that the x86 detour cannot see is a site line:
#
#   site  name  address  arg...
#
#   address  where the copy starts in Wow.exe; a mid-function hook there runs the point's Before
#            handlers, flagged WXL_POINT_CALL_INLINED (no Replace, no After: a copy has no call to
#            replace and no single return).
#   arg      where each argument lives at that address: a register (eax ecx edx ebx esi edi ebp) or
#            a stack slot ([esp+8], [ebp-0x10]); a handler that writes one writes the copy's.
#
# `generate_points.py --coverage --binary Wow.orig.exe` compares the calls of each point in Wow.exe
# with its call sites in the fork, which is how a missing site line is found.
#
# A function the x86 compiler inlined can still be a point on x86, de-inlined:
#
#   deinlined  name  parent
#
#   name    a point listed above with address `-`.
#   parent  a function of Wow.exe that holds name's inlined copy: a point with an x86 detour, or
#           a function the fork tags with an address that is no point (named with its parameter
#           types when the fork overloads it). While name has handlers, the x86 runtime replaces
#           parent's body with its recompilation from the fork (core/src/deinlined/, written by
#           core/tools/extract/extract.py), in which name is a function of its own, entered
#           through the point. A function inlined into several has a line for each, so that it
#           fires from all of them as on x64. Listed for every runtime and mod in
#           sdk/include/wxl/deinlined.def.
#
# A name the fork overloads carries its parameter types as the fork spells them, without spaces
# after commas: M2Init(uint8_t*,uint32_t,M2Data&). Its C identifier adds the types' bare names
# (M2Init_uint8_t_uint32_t_M2Data).
