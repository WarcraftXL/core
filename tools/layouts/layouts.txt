# layouts.txt: the struct layouts core depends on, measured on the client fork compiled 32-bit.
#
# This is the declared, human-edited record of which types and members matter. measure_layouts.py
# turns it into core/offsets/layouts.def (sizeof / offsetof as MSVC lays the fork's headers out
# for Win32) and compares every hand-written constant of client/warcraftxl/include/wxl/offsets
# (the inventory in core/offsets/audit-handwritten.md) with its measurement.
#
# Syntax
#   type <id> <header[,header...]> <C++ type>      a type to measure; headers are relative to the
#                                                  checkout; the id names the rows in layouts.def
#     sizeof                 <refs>                sizeof(type)
#     <member designator>    <refs>                offsetof(type, designator); a.b and a[i] allowed
#     sizeof(<designator>)   <refs>                sizeof of that member (strides, byte sizes)
#   skip <refs> :: <reason>                        hand constants that are not a struct layout
#
#   <refs> is "-" or a comma-separated list of hand constants, <header stem>:<name>, e.g.
#   engine/GxDevice:kD3dDevice (the stem is the path under include/wxl/offsets without .hpp; a
#   name repeated inside one header carries @<line>). A ref may add a bias, +0xNN, when the hand
#   constant is defined relative to an enclosing block: hand value = measured + bias.
#   "#" starts a comment. The tool refuses to run unless every inventory row is referenced
#   exactly once, so nothing is dropped silently.
#
# Where the hand comment and the fork's member name disagree about what a slot IS, the entry maps
# the hand constant onto the fork member that sits at the hand offset and says so in a comment;
# the comparison is about offsets, the naming question is left to the reader.
